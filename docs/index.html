Agent BEV Guard

多源证据融合的 Agent 行为取证 —— 检测并重建 Agent 的未授权数据流

kernel sensors (eBPF/bpftrace) MCP tool gateway hash-chained audit log provenance graph + consistency rules zero deps · Python 3.10+

01场景

一次 Agent 会话中发生的三件事——单独看每件都不一定致命，放在一起就是一条证据链：

14:03:24 · 内核观测

/home/Docs/image_123.jpg（confidential）
14:03:25 · 内核观测

14:03:26 · Agent 自报

——与系统观测矛盾

03Provenance 图：谁碰了什么

节点 = run / 进程 / 文件 / 端点 / 声明；每条边标注来源传感器与身份确定度。红色边构成告警的证据链。

04一致性规则 → 结构化结论

告警由「规则是否成立」决定；confidence 只描述证据强弱（heuristic score，非概率）；sensor health 只描述观测完整性。三者不混成一个分数，也没有单一 risk_score。

05改改条件试试：规则怎么响应

规则一、三豁免——但规则二照样响：说了没发就是发了，发去哪都算矛盾。
证据不齐时，"没发现问题"自动变成"无法下结论"——absence of evidence ≠ evidence of absence。
规则二输出 NOT_APPLICABLE（不适用），而不是"没违规"——两码事。
哈希链断裂被定位到具体记录，报告 CLI 拒绝出报告。

06审计日志：append-only + 哈希链

每条记录的 hash = SHA-256(上一条 hash + 本条内容)。改任何一条、删一行、插一行，链都会断在具体位置。

⛔ 哈希链在记录 #4 处断裂 —— egress bytes 被篡改（2,300,000 → 9,999,999）。报告 CLI 拒绝基于被污染的证据出报告（exit 3）。

固定设计原则

不存 payload
审计日志只有行为 metadata（路径/字节数/动词），日志本身不能成为泄露通道。
允许不确定，不伪造确定性
每条事件有明确的 identity 状态（DIRECT/INFERRED/UNKNOWN），而不是必须有 identity。
pid 单独永不归因
因果归因键是 (pid, pid_start_ts)；宁可 UNKNOWN，不制造假的因果链。
缺证据 ≠ 没发生
不知道文件大小时对账结论是 INSUFFICIENT_EVIDENCE；传感器降级时阴性结论变成 INCONCLUSIVE。
引擎不聚合
规则引擎只产原始 findings，incident 归组只在报告层——"触发三次"与"压成一次"永远可区分。
先验链，后出报告
报告生成前先验证审计日志哈希链，链断则拒绝出报告。
